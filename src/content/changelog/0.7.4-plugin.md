Two new tracks join the four commands, and the Codex adapter now covers the desktop app alongside the CLI.

## Improvements

- `/archcore:plan research` runs a gated investigation: frame the questions, gather the evidence, conclude with a recommendation and a next action. It produces one `rnd`, related to the `idea` or `prd` the research informs. Use it for "investigate X" and "compare the alternatives for Y".
- `/archcore:review` gains a closeout track. Say "close out the feature" and the skill verifies the plan against the branch diff, merges the document updates you approve, and moves the finished drafts to `accepted`. A status changes only after you confirm the transition.
- An open `rfc` resolves through the decision track. Say "we accepted the proposal" and the skill enters at `decision.resolve`: the proposal becomes an `adr` or is marked rejected.
- The Codex adapter covers the Codex desktop app as well as the CLI. Both surfaces share one binary, one `~/.codex/config.toml`, and one plugin install, so the agent id stays `codex-cli` and no artifact distinguishes them.
- `/archcore:init` names both Codex surfaces in its host question, and reports the two consents Codex wiring waits on: project trust, and hook trust under `/hooks`.
- The `sdd` track holds the content boundary between a `prd` and the documents below it. A `prd` states the wanted outcome and the measured goal; the graded behavior goes in the `spec`, and the phases go in the `plan`. See [Content ownership](/concepts/document-types/#content-ownership).
- Plugin-authored documents follow a prose profile. A type whose lines instruct or obligate is written to the STE half; a type whose lines argue or describe is written to the ISO half.

## Fixes

- Host detection keys Codex on `CODEX_THREAD_ID` rather than `CODEX_HOME`. Codex injects the first into every model-run shell command; the second is set by the user and exported by nothing, so the branch never fired.
- A Codex session no longer loses hook output. Codex discards a hook's entire output when its stdout starts with `{` or `[` and does not parse against the event shape, so `bin/session-start` now emits one `SessionStart` document and splices its advisories into `additionalContext`.
- Every hook command in the Codex config carries an `ARCHCORE_HOST=codex` prefix. A Codex `SessionStart` payload carries no `turn_id`, so the stdin heuristic could not resolve the event on its own.
