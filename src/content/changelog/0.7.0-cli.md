Hook policy moved out of the Archcore plugin and into the CLI. One binary now decides what a hook does, and each host gets the same guards through a protocol adapter instead of a per-host script.

## Breaking changes

- The MCP server no longer serves track prompts. The five prompts that drove PRD, ISO, sources, architecture, and standard cascades are removed, and `prompts/list` answers with a JSON-RPC method-not-found. Track orchestration lives in the plugin's [`/archcore:plan`](/plugin/skills/#archcoreplan) skill, so it has a single owner.
- Archcore plugin v0.7.0 or later is required for hooks to fire through the plugin. Older plugin releases ship their own hook scripts and do not delegate here.

## Improvements

- One command serves every hook event: `archcore hooks <host> <event>`. Hosts are `claude-code`, `cursor`, `gemini-cli`, `copilot`, `codex-cli`, and `opencode`. Events are `session-start`, `pre-tool-use`, and `post-tool-use`.
- A host dialect layer replaces the per-host implementations. It carries the context envelope, the deny style, and the event names each host expects, so a host that reads `additional_context` and a host that reads a `hookSpecificOutput` wrapper run the same guard.
- The write guard runs first and alone on every pre-write event. Its verdict is computed before any advisory work starts, so a failure in the injection path cannot change the decision on your edit. It refuses exactly what the MCP write tools refuse, because both consult the same predicate.
- Code-alignment injection is now a CLI advisory. It ranks by deepest matching directory, injects at most 3 documents and 2048 runes, and covers `rule`, `cpat`, `adr`, `spec`, and `guide` only.
- Post-write checks report structure problems, relation cascades, and precision findings. The precision lexicon adds `spec`-specific checks: `SHALL` instead of BCP 14 modals, oversized bodies, compound requirements, and subjectless passive clauses.
- The staleness advisory is part of the session-start recap. It names the documents that mention directories that moved, rate-limited to once per 24 hours per project.
- GitHub Copilot receives install wiring at `.github/hooks/archcore.json`. Its pre-write event carries only a permission decision, so the write guard runs there and the injection does not. A deny is a `permissionDecision` document on stdout with exit code 0, because Copilot discards the reason on a non-zero exit.
- `archcore update --check` reports whether a newer version exists. The result is cached for 24 hours, network-bound to about 500ms, and always exits 0, so a hook can call it safely.
- `archcore doctor` reports whether each wired host can act on its hook config. It stays silent about a detected host that was never wired, rather than reporting it healthy.

## Misc

- `archcore hooks install` and `archcore doctor` report when an older Archcore plugin is installed alongside the CLI. Both sets of hooks fire, which duplicates output but never changes a verdict.
