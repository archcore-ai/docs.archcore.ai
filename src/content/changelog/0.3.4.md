The Archcore plugin lands on the Claude Code and Cursor marketplaces. The CLI remains the engine that exposes the document tools and validates `.archcore/`. The plugin is the IDE surface that puts those tools inside your agent.

## Highlights

- 18 `/archcore:*` slash commands: 11 intent commands (`/archcore:context`, `capture`, `decide`, `standard`, `plan`, `review`, `actualize`, `status`, `graph`, `bootstrap`, `help`), 6 multi-document tracks (`product-track`, `architecture-track`, `standard-track`, `feature-track`, `sources-track`, `iso-track`), and `verify`
- 2 sub-agents: `archcore-assistant` (multi-document writer with full MCP access) and `archcore-auditor` (read-only documentation health reviewer)
- 4 lifecycle hooks: auto-load the `.archcore/` index on session start, block direct writes to `.archcore/` files, warn before edits drift from documented context, and validate cascade staleness after MCP mutations
- 17 pre-registered document types: PRDs, ADRs, RFCs, rules, guides, specs, plans, task-types, code patterns, and the ISO 29148 cascade (BRS / StRS / SyRS / SRS)
- A bundled CLI, auto-downloaded on first use. It respects an existing `archcore` on `PATH` and honors `ARCHCORE_BIN` and `ARCHCORE_SKIP_DOWNLOAD` for offline or pinned setups
- Always-on context rules: every agent session starts with the document model and the MCP-only write rule already loaded

## Meet the plugin

The CLI does the work. `archcore mcp` exposes the document tools, `archcore validate` lints the cascade, and `archcore init` scaffolds a fresh `.archcore/`. The plugin turns those tools into commands you type and hooks that run on their own. Agents pick up the project context when a session opens, and a hook blocks direct writes to `.archcore/` files, so every write goes through MCP. Install instructions live at [/plugin/install/](/plugin/install/).
